## Protocol

Each independently initialized case starts at 20 C with calm exterior wind and an unlimited 75-unit virtual-air source. Heat for 600 physical seconds, remove the source, and cool for 80 seconds. Response scale is 1 throughout. Solver settings and machine/JVM metadata are included in each raw report. These runs measure finite-time sensitivity, not settled equilibrium or performance.

Padding is the factory's geometry parameter: dimensions are `(12 + 2*padding)` by `(7 + groundDepth + topPadding)` by `(12 + 2*padding)`. The house remains 10x10x5 with unchanged openings, materials, and source position relative to the ground surface. Increasing depth shifts the house upward with the surface; it does not bury it. Padding 8/16 at depth 3 gives 28x18x28 / 44x26x44. Padding 8 at depth 6 gives 28x21x28. Outer material is insulated; exterior air exchanges heat by advection, without an additional diffusive bath. No fluid is present in these houses.

House fields contain 500 matched positions, including building material. Each position stores temperature followed by three cell-centered velocity components. Material velocities are zero placeholders. Temperature RMS includes all 500 positions; velocity RMS includes only air positions and all three components. `maxVelocity` is a component error, not a vector-norm error. The late mean is a trapezoidal average over physical seconds 540-600. Within-window ranges include residual warming drift. The per-step probe series and normalized second difference help distinguish smooth drift from rapid oscillations; no spectral or spatial-refinement claim is made.

The final boundary/ground harness checkpoints each fully finished case with root `complete=false`, then writes `complete=true` after the requested cases finish. Partial checkpoints must not be interpreted as whole-run success. `timesteps.json` predates this checkpoint addition; its nine completed rows and physical-time checks establish completion. Timings include solver steps only, but the process also reconstructs diagnostic fields; use the prior dedicated performance reports for cost comparisons.

## Reproduction

With the normal build environment, run `:paradyne-lib:coupledAirBenchmark` three times, setting `-PcoupledAirMode=timesteps`, `boundaries`, and `ground`, with distinct `-PcoupledAirReport=<path>` values. Use `-PcoupledAirQualificationStep=0.5` for boundary/ground runs. Remaining controls are `COMPACT_CACHED`, cached sampling `true`, and `CACHED_TRACE`. The `timesteps` mode selects its own three steps.

For one recoverable case, use mode `qualification-case` and `-PcoupledAirQualificationCase=0,8,8,3` (opening 0/1/2, horizontal padding, top padding, ground depth). Extra properties are documented in `paradyne-lib/build.gradle`.

This environment used cached Java 21 and JUnit/Gson jars to compile all main/test sources in the pure `heat.air` package, then ran the JUnit launcher and the benchmark main class directly. JVM options were `-Xms512m -Xmx1g -XX:+UseG1GC`. Positional benchmark arguments were:

```text
<report> <timesteps|boundaries|ground> COMPACT_CACHED true CACHED_TRACE long 0.5
```

Run `python docs/benchmarks/air-qualification-2026-10-20/summarize.py` to validate all row counts, progress, rejection status, and late-window coverage, and regenerate `comparisons.json`. The script uses only the Python standard library.

The padding-24 follow-up uses the same existing benchmark code, freshly compiled and tested. Its positional arguments are:

This is a 60x34x60 domain (122,400 spatial cells).
